WHAT I CREATED

三份文档，一套可检查的流程。

01 / SKILL

把业务规则写成操作规范

接收与分类、票面读取、项目与科目、双重去重、资料条件、状态与异常。保留修订记录，说明哪些规则已经被后续版本覆盖。

02 / README

给接手者一个入口

说明工作流如何组织、数据与文档如何衔接、执行前应核对什么，减少流程知识只存在于个人记忆中的情况。

03 / END-TO-END MAP

把责任和证据串起来

从收到发票到付款确认、供应商通知与归档，区分自动准备、业务审批、银行操作和会计交接。

来源：本人提供的 SKILL、README 和 SILVERLINE AP END TO END WORKFLOW。原文含内部信息，留在本地。流程文档可以核对；未用未经测量的节省时间、准确率或付款金额作为成绩。

PROCESS / EVIDENCE

每一步都有输入、输出和停止条件。

环节形成的工作产品检查与异常
接收与识别票面字段、原文件索引、扫描识别记录不是发票的文件另行分类；金额回看页面。
去重与归属文件哈希＋业务字段检查、项目实体匹配同票重扫、相似实体、已在其他路线付款时暂停。
资料与准备缺项表、付款准备候选及理由业务批准与资料齐全分别记录；例外交由负责人。
付款与确认由有权限人员处理银行动作；依据回执更新状态批准、排期、已付分开；回执金额、日期、实体不符时不改已付。
归档与交接发票、确认与匹配证据，供会计复核保留原文件与版本；通知和外部动作需独立授权。
VERSION / SCOPE

规则收紧，执行范围也随之改变。

后续 10 月 8 日修订：只更新人工已建立的批次和已有表格；每张实际发票对应一行。不自动建立新批次，不从历史总账重新导入旧行，不随意移动原始文件。早期端到端设计保留为历史，复用时先确认适用版本。

MY CONTRIBUTION

业务到系统的翻译

把财务操作拆成字段、状态、判断、责任人与完成证据，让接手者知道下一步做什么、何时应停下来核对。

CONTROLS

把异常当作流程的一部分

实体冲突、部分付款、缺少资料、历史重复和旧回执分别处理，避免用一个“完成”掩盖不同状态。
